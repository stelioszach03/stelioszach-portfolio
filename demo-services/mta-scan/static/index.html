          What is live and what is not. The map, the counters and the station list are read from this deployment’s own database, filled by the collector from the public MTA GTFS-Realtime feeds. If the feeds are unreachable or the model has not accumulated enough history yet, this page says so rather than showing anything invented. The replay section is not live: it is a frozen artifact, shipped with this demo under data/replay/ and produced by the project repository's scripts/run_replay_eval.py. The same numbers are served by GET api/replay; the page reads the static copy so the measured result is on screen before the first API call returns.

          Honesty about the evaluation. 216 rows, 16 labelled positives, 3 incidents, 6 stations. That is a sanity check on a representative labelled scenario, not a benchmark, and the incident labels are not official MTA annotations. The online model wins on recall and on lead time and loses on false alarms — both directions are in the table. The replay CSV’s stop_id column is synthetic, so station positions here are resolved from the real MTA GTFS by station name. The regressor is linear, so during a sharp change it can predict a negative headway; those values are printed as produced rather than clipped to zero.
